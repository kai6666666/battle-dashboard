## 〇、设计原则（五条铁律）

1. **契约合规**：新列"DDL 注释 = 表头名"（精确相等）、列名纯 ASCII、`row_id` 保持首列
   ——满足数据库 `validateDDLTextAgainstHeaders` 的逐列精确匹配；
2. **命名规范**：表头 = 中文（**对齐 DND 模块读取词**，如 "AC"/"先攻加值"）；列名 = 英文小写下划线（贴合各表同族风格，任务/纪要类用 `*_text`）；
3. **插入位置**：一律**追加到表尾**（原列序零扰动）；若表尾有"表级 CHECK 行"（仅任务表），新列插在该行**之前**；
4. **宽松兼容**：全部可空（无 NOT NULL）、尽量不加 CHECK（枚举语义写入 note）——兼容旧数据与两种世界观；
5. **三处同步**：`content[0]` 表头 + `sourceData.ddl` + `sourceData.note`（列定义清单），流程复用「13 列合并」工具模式。

## 四、实施指引（将来动手时）

1. **目标文件**：`骰子模板（仙SQL）.json`（或其融合版）——对 9 张表执行"三同步"；
2. **工具**：复用 `merge_columns_into_A.py` 的"表头插入 + DDL 行插入 + note 插入 + 断言自检"模式；
3. **校验链**：契约复检（0 违规）→ SQLite 逐表建表 → 物理名无新冲突 → 导入实测；
4. **特别注意**：任务表新列必须插在表级 CHECK 之前（否则 DDL 语法错误）；
5. **兼容性**：全部可空——现有数据零迁移即可导入。
