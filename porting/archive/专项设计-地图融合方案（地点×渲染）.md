# 专项设计 · 地图融合方案（地点 × 渲染）—— 探索/战斗数据源重构评估

> 生成时间：2026-10-05
> 问题：① 骰子「地点功能」与 DND「地图功能」能否融合？② 探索/战斗地图能否改用「世界地图点 + 地图元素表」（+坐标/ SVG 列）呈现相同效果？③ 多方案与优缺点。
> 证据：`features/map/map-view-model.ts`（270 行）、`features/map/map-visualization.ts`（438 行）、`UIMap.js`（874 行）、`ExplorationMapManager.js`（464 行）。

## 〇、结论速览

- **Q1：能融合**——两者是「互补型重叠」：骰子=**内容/浏览层**，DND=**图形渲染层**。融合形态 =「同一地点数据源 → 双视图（叙事画廊 + 图形地图）」。
- **Q2：探索地图——可以**（需补渲染列；效果由渲染器保证，可一致）；**战斗地图——分层**（场景层可挂世界地图点；战术层必须留在战斗三表）。
- **Q3：三方案**（甲桥接 / 乙单源升级 / 丙图层化重构），推荐见 §四。

## 一、两套系统现状（代码级）

### 1.1 骰子侧：地点功能 = 叙事画廊

- 数据源：**世界地图点**（name/region/locationType/description/importance/exploreStatus）+ **地图元素表**（name/type/location/description/status/**interactions**）+ 角色表（NPC/玩家按位置分组）。
- UI：全屏 overlay（`acu-map-overlay`）＝ **地区标签页 → 热度排序**（角色数+元素数）→ **地点缩略卡列表 + 焦点区**；emoji 图标、角色头像、交互选项。
- 特征：**逐条维护、文本/卡片式、无图形渲染**。

### 1.2 DND 侧：地图功能 = 图形渲染

- 探索：**整包式**——SVG 整图（AI 生成/缓存）+ 当前显示覆盖（`EXPLORATION_Map_Data`）。
- 战斗：**战术层**——网格 + 底图（`COMBAT_Map_Visuals`）+ Token（`COMBAT_BattleMap`）+ 行动者（`COMBAT_Encounter`）。

### 1.3 性质归纳

| 维度 | 骰子地点 | DND 地图 |
|---|---|---|
| 形态 | 叙事画廊（文本/emoji/卡片） | 图形渲染（SVG/网格/Token） |
| 数据粒度 | 逐条（地点行/元素行） | 整包（结构 JSON/SVG） |
| 更新方式 | AI 改行 | 生成/重绘 |
| 优势 | 可读、可维护、可热度 | 直观、可战术、可沉浸 |

## 二、Q1：融合可行性

**能。** 融合动作 = 统一「地点」的**身份与元数据**（世界地图点 = 地点主数据），在视图层提供**两个入口**：

1. **画廊视图**（骰子原版浏览，读世界地图点/元素表）；
2. **图形视图**（DND 渲染：探索 SVG / 战斗网格）。

两者共享：「当前地点」判定（全局表三级字段）+ 地点身份（名称/`location_id`）+ 元素数据（可叠加到图形视图）。

## 三、Q2：改用「世界地图点 + 地图元素表」评估

### 3.1 探索地图：可行（需补 3 类数据）

| DND 渲染所需 | 现来源 | 改后落点 |
|---|---|---|
| locationName | 探索地图数据.LocationName | **世界地图点.详细地点**（已有） |
| MapStructureJSON | 探索地图数据 | 世界地图点**新增列**（或保留专表，见方案） |
| SVG 本体 | IndexedDB+Chat 缓存 | **仍走缓存层**（不建议入表：单行几十 KB 大文本） |
| 当前显示覆盖 | 探索地图数据.当前显示地图 | 世界地图点**新增列**（单选标志） |

**效果**：只要渲染器读得到结构+图，效果与现状**一致**；若元素表加坐标，还能叠加「元素图层」（超出现状）。

### 3.2 战斗地图：分层，不能整体迁移

- **场景层**（地点背景/底图生成场景）→ 可挂世界地图点（`SceneName` ↔ `详细地点` 关联）。
- **战术层**（单位/坐标/大小/Token、网格 Config、先攻/当前行动者）→ **必须留在战斗三表**（动态数据，与遭遇系统耦合；元素表语义=场景元素，不应承载战斗单位）。
- 结论：战斗地图「**场景件**可复用世界地图点；**战术件**保持战斗域」。

### 3.3「相同效果」的边界

**效果由渲染器决定，不因数据位置改变**——只要「结构 + 图 + 覆盖标志」齐备，探索地图效果可 100% 复现；数据源改造是「存放位置」的选择题。战斗地图同理：战术渲染依赖战术表（已并入基座）。

## 四、Q3：方案集

### 方案甲 · 桥接（最小改）

- 内容：探索地图数据表**补入基座为第 21 表**（原样 + `location_id`）；世界地图点/元素表不动（可选加坐标）。
- 浏览：画廊读世界地图点；渲染读探索地图数据表；以 `location_id` 对齐。
- 优点：DND 模块**零改造**；保留专表语义（「当前显示地图」清晰）；风险最低。
- 缺点：仍两套地点表，需靠 ID/名称同步（AI 只维护一张就旧）；「唯一源」只算名义达成。
- 工作量：**小**（数据层 +1 表 +1 列）。

### 方案乙 · 单源升级（推荐目标态）

- 内容：**世界地图点升级为地点主表**——新增 `map_structure`（整图 JSON）、`current_map`（当前显示标志）、`map_updated`（可选）；探索地图数据表**不再并入**（其数据并入新列）；元素表加 `coord`（坐标）+ `icon`（可选）。
- 绑定：探索渲染 locationName=详细地点；结构读新列；SVG 仍缓存；元素图层可叠加（可选增强）。
- 战斗：保持战斗三表；`SceneName`=详细地点。
- 优点：**真正单一地点源**（叙事+渲染同行）；AI 维护一处；§6.2-6「唯一源」落地；画廊/图形同数据；后加元素图层零阻。
- 缺点：世界地图点变宽（12→14+ 列）；大 JSON 进表（写表质量/锁预检需观察）；DND 读表列名适配（b5 适配层）。
- 工作量：**中**（模板改造 + 模块列映射）。

### 方案丙 · 图层化重构（产品级，远期）

- 内容：探索地图重构为「**底图 + 图层**」（与战斗地图同构）：底图列/SVG + 元素图层（元素表坐标）+ 角色图层；AI 生成流程从「整图」改为「底图 + 元素定位」。
- 优点：**动态地图**（元素状态、角色移动实时反映，无需整图重绘）；两模式共用一套渲染器；沉浸与战术统一。
- 缺点：改造最大（探索渲染重写 + 元素坐标生成流程）；需要元素定位的 AI 稳定性验证。
- 工作量：**大**（b4 之后专批）。

### 方案对比矩阵

| 维度 | 甲 · 桥接 | 乙 · 单源升级 | 丙 · 图层化 |
|---|---|---|---|
| 地点源唯一性 | 名义（双表+ID） | **真实（单表）** | 真实（单表） |
| DND 模块改造 | 零 | 列映射（小） | 渲染器重写（大） |
| 模板改造 | +1 表 +1 列 | +3 列（含可选） | +4 列 |
| 效果 | 现状复现 | 现状 +（元素图层可选） | **升级（动态图）** |
| 风险 | 最低 | 低-中 | 中-高 |
| 落地批次 | b4 前数据层即可 | b4/b5 | b6+ 专批 |

## 五、推荐路线

- **目标态**：方案乙（单源升级）——满足「地图数据源唯一」裁决且成本可控；
- **稳健路径**：甲先行（b4 前补表保渲染跑通），乙作为「地点主表升级」在 b4/b5 期间切换；
- 丙留作远期增强（元素图层/动态化），不阻塞主线。

## 六、若拍板方案乙的模板改动清单（预告）

1. 世界地图点 +3 列：`map_structure` / `current_map` / `map_updated`（后两者可合并）；
2. 地图元素表 +2 列：`coord` / `icon`（可选，为图层预留）；
3. 探索地图数据表：**不并入**（草案第 21 表方案相应撤销）；
4. 全局数据表：+`场景描述`/`战斗模式`（与模式开关一并拍板，见《地图数据源详解》§6.1）。
