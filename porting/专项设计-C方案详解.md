## 一、C 要解决的根本问题

现状（档 1）：地图 = 「AI 整图」，一张 SVG 里画死一切。三个固有缺陷：

| 缺陷 | 说明 |
|---|---|
| 不精确 | AI 自由发挥，SVG 坐标与真实结构无保证对齐 |
| 不可动 | 元素状态/角色位置变了 → 只能重绘整图（AI 再生成） |
| 不可点 | 图是"一张画"，元素点不了（骰子侧点击→详情的能力断裂） |

C 的解法：**三分离**——结构（数据）/ 氛围（美术）/ 交互（图层）各自独立，由渲染器合成。

## 三、数据模型设计（三层坐标体系）

```
L0 世界层：世界地图点 + 坐标(x/y)           → 世界总览图（地区布点）
L1 地点层：地点结构 JSON（rooms/doors/…）    → 探索图区域层（已有坐标！）
L2 元素层：地图元素表 + 坐标/大小/形状/图标  → 元素点位层（点击交互）
L3 角色层：角色表.所在地点（+可选 x/y）      → 头像点层（动态）
```

### 表列设计（预告，落基座时以 v4 扩列批次执行）

| 表 | 新列 | 用途 |
|---|---|---|
| 世界地图点 | `坐标`（coord "x,y"） | 世界总览图布点 |
| 世界地图点 | `map_structure` / `current_map` / `map_updated` | 探索结构 + 覆盖锚（与 B/乙 方案共享） |
| 地图元素表 | `坐标`（coord，可空）、`大小`（size，可空）、`形状`（text，可空）、`图标`（可空） | 元素点位、占地、几何、自定义图标 |
| 全局数据表 | `战斗模式` / `场景描述` | 模式开关 + 生成参数（已列差异表） |

> 坐标约定：**百分比坐标系（0-100）**——与渲染画布解耦，任意尺寸自适应；缺失时系统自动布局（按交互序环形/网格分布），AI 可给初值、人工可微调。

## 四、渲染架构（图层栈合成）

```
┌─ Layer 4 交互层（HTML/JS）──── 点击/悬停/详情卡/交互按钮
├─ Layer 3 角色层（绝对定位）─── 头像点（读角色表，动态移动）
├─ Layer 2 元素层（SVG/定位）─── 元素图标 + 状态皮肤（已破坏/已开启…）
├─ Layer 1 区域层（SVG path）─── rooms/doors/features 轮廓（确定性绘制·主题皮肤）
├─ Layer 0 氛围底图（可选）───── AI 生成"仅背景"（不承担精确性）
└─ 基准：百分比坐标系（0-100）＋ 战斗模式时叠加 UI 网格（先例已有）
```

- **确定性渲染器**：结构 JSON → SVG path（墙壁/门/物件），支持四主题皮肤（配色/描边/纹理/阴影参数表）；
- **AI 氛围底图**：可选增强层——提示词约束为"只画环境氛围/材质，不画结构线"，允许误差（只是背景）；
- **经典模式开关**：保留现有"AI 整图"路径作为兜底（用户可切回）。

## 五、AI 生成管线重设计

**现状**：`structure(AI) → svg(AI整图)`｜**C 化**：

```
Step1 结构生成（保留·AI）        rooms/doors/features（含坐标）→ 存表
Step2 氛围底图（可选·AI）        约束提示词：仅背景材质，不画结构
Step3 程序合成（前端·0 成本）     区域层+元素层+角色层 确定性渲染
Step4 元素坐标（AI或系统）        ① AI 维护元素表时填 coord ② 缺失→自动布局 ③ 远期拖拽微调
```

**收益**：AI 调用从"每次整图"降为"可选氛围图"——**成本↓、延迟↓（秒级出图）、可离线**。

## 六、交互升级清单（C 的核心卖点）

| # | 能力 | 说明 |
|---|---|---|
| 1 | 元素点位点击 | → 详情卡（名称/类型/描述/状态/**交互选项按钮**——现成字段直接可用） |
| 2 | 状态驱动皮肤 | 元素"状态"列变化 → 图标样式实时变化（如"已破坏"→裂痕/变灰） |
| 3 | 房间/区域点击 | → 区域描述（rooms.description） |
| 4 | 角色层动态 | 角色移动 = 改一行"所在地点"→ 头像点移动，**无需重绘地图** |
| 5 | 世界总览图 | 地区分组 + 地点布点（探索状态着色）→ 点击进入地点图 |
| 6 | 探索状态联动 | "探索状态"列 → 迷雾/未探索样式 |
| 7 | （远期）编辑模式 | 拖拽元素/房间微调，坐标持久化 |

## 七、实施分期（C1 → C4）

| 期 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| **C1 元素图层叠加** | 在**现状 AI 整图上**叠加元素点位层（坐标缺失自适应布局）；可先在战斗网格试点 | 1 批 | 低（不动渲染主链） |
| **C2 确定性渲染器** | 探索图切为"程序区域层 + AI 氛围底图（可选）"；主题皮肤；经典模式开关 | 2-3 批 | 中（视觉落差需调） |
| **C3 世界总览图** | 世界地图点坐标 + 地区分组布点 | 1 批 | 低 |
| **C4 动态化/编辑** | 状态皮肤、角色层、迷雾、拖拽编辑 | 持续 | 中 |

建议窗口：**C1 可作 b11/b12 期间的低成本试点**；C2+ 待主线（b4-b10）完成后按试点效果评估。

## 八、难点与对策（诚实清单）

| 难点 | 对策 |
|---|---|
| 视觉落差（程序图 vs AI 手绘图） | 主题皮肤渲染参数 + 纹理/滤镜 + **AI 氛围底图混合** + 经典模式开关兜底 |
| 坐标对齐 | 点位只对**程序层**负责；AI 底图不参与对齐（背景自由） |
| AI 坐标质量不稳定 | 坐标可空 + 系统自动布局兜底 + 人工微调（远期拖拽） |
| 大 JSON 入表风险 | 结构 JSON 房间级入表；元素点行进元素表（粒度分工）；note 标注"系统维护" |
| 性能 | 纯 SVG/DOM 合成（轻）；战斗侧先例证明可行 |
| 回退成本 | 经典模式开关 = 一键回退 AI 整图路径 |

## 十、结论

1. C **技术上可行且已有半个身体**（结构含坐标 + 战斗侧图层先例 + 图标/头像/主题体系）；
2. 但工程量与视觉风险决定了它**不适合作为融合首期**——定位 Phase 2 增强；
3. **无论最终是否走 C，坐标列都值得现在加**（成本低、对 B/D/乙全兼容）；
4. 最小验证路径：**C1 = 一次"元素点位叠加"试点**——用最小代价验证"C 的体验增益是否真实"。
