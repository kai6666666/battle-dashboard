# 专项设计 · 丙方案详设 —— 图层化深度融合（探索地图重构）

> 生成时间：2026-10-05
> 定位：《专项设计-地图融合方案（地点×渲染）.md》**方案丙** 的展开稿；与《专项设计-地点功能与地图功能融合方案对比.md》**方案 C（深度融合）** 同方向。
> 关键前提：甲/乙解决「**数据源归置**」；丙解决「**渲染范式升级**」——丙不替代甲乙，而是叠加其上。

## 一、一句话定位

把探索地图从「**一张 AI 整图（静态快照）**」升级为「**底图 + 图层（动态地图系统）**」——与战斗地图同构，支持元素交互、状态实时反映、世界总览。

## 二、效果目标（做完长什么样）

1. 探索地图 = 画布：底图（手绘风保留）+ **元素标记层**（可点击）+（可选）角色层；
2. **点击地图上的「铁笼 / 雕像 / 机关」→ 弹出元素详情**（描述 / 状态 / 交互选项——数据即元素表）；
3. **动态性**：AI 改元素表（新增 / 状态变更）→ 标记层实时变化，**无需重绘整图**；
4. （子项）**世界总览图**：世界地图点布点 + 地区分组，世界视图可视化；
5. **架构统一**：探索 / 战斗共用一套「分层渲染」（一份代码，两模式）。

## 三、技术架构（三条子路线，可分期独立落地）

### 丙-1 · 交互标记层（「整图 + 语义标记」，推荐首落）

- 思路：**保真整图不动**——AI 生成 SVG 时**同步在图元上打语义标记**（`data-element-name="铁笼"`）；前端内嵌 SVG 后直接绑定 `[data-element-name]` 点击 → 元素详情浮层。
- 降级路径：AI 未稳定输出标记 → 退「热点圆点层」（热点坐标 JSON，相对百分比）→ 再退纯整图（渐进增强，不破坏基本盘）。
- ✅ 手绘保真 100%；坐标对齐问题**天然消解**（点击的是图形自身）；实现量中。
- ⚠️ 依赖 AI 标记输出稳定性（prompt + 生成后校验）；无标记时交互缺失。

### 丙-2 · 真图层组装（完整图层化）

- 思路：**底图 = 空图**（房间 / 装饰，无道具），元素由前端用 SVG 图标层渲染（坐标 + 图标映射），角色用 token 层。
- ✅ 完全动态（表变图变）、统一渲染器、可切换「极简 / 战术风」。
- ⚠️ 手绘感降级（图标风）；AI 布局管线重设计（三阶段：结构 → 底图 → 元素布局）；坐标定位稳定性待验证。
- 定位：远期完整形态；与乙（单源表）天然配套。

### 丙-3 · 世界总览图（独立增强，可先行）

- 思路：世界地图点加坐标列（x/y 或地区内布点）→ 生成「世界布点图」（节点 + 连线 + 地区分组）。
- ✅ 数据源现成、独立于探索渲染。
- ⚠️ 布点数据需维护（AI / 人工）；与探索整图不同构。

## 四、数据层设计（模板 v4+ 增量）

| 表 | 新增列 | 分量 | 用途 |
|---|---|---|---|
| 地图元素表 | `坐标`（coord "x,y"）、`图标`（icon）、`形状`（可选 shape） | 丙-1/2 | 元素定位与标记 |
| 世界地图点 | `x`、`y`（或 `布点` coord） | 丙-3 | 世界总览布点 |
| （丙-1 降级用） | `热点JSON`（可选） | 丙-1 | 无标记时的热点层 |

- 坐标格式：复用既有 `coord` 型解析（"x,y"）——与战斗 Token 同款。
- **同步桥（推荐）**：结构 JSON 生成时的 `features(x,y,type)` → 生成后提取，**建议回写**元素表坐标（同语义元素：机关 / 宝箱 / 雕像…），让「叙事元素」与「图上元素」同源。

## 五、渲染层设计（分层 DOM，对齐战斗地图现成结构）

```
.dnd-exploration-inner
 ├─ 底图层（SVG / bg）
 ├─ 元素标记层（.dnd-map-element [data-name]）   ← 丙-1/2 新增
 ├─ 角色层（可选，头像 tag）                      ← 丙-2
 └─ 交互 overlay（热点 / 浮层）                   ← 丙-1
```

- 复用现有：缩放 / 平移（applyTransform）、MiniMap 容器、重绘按钮；
- **统一渲染器**：把战斗地图的分层注入逻辑（bg / grid / token / overlay）抽为共用模块，探索 / 战斗两模式共享。

## 六、AI 管线改造

- **丙-1**：svg prompt 增量——「为每个可交互元素添加 `data-element-name` 属性或输出热点 JSON」；生成后校验（缺标记 → 降级）。
- **丙-2**：三阶段——结构（含 features）→ **底图**（去元素）→ **元素布局**（坐标吸附到房间边界框内）。
- **丙-3**：布点 prompt（世界点 x/y，地区分组布局）。

## 七、体验与交互

- 点击元素 → 浮层：元素描述 / 状态 / **交互选项**（数据即元素表，与画廊视图一致）；
- hover 高亮（CSS 滤镜 / 描边）；
- 角色层（丙-2）：当前地点角色头像标签；
- 教程：地图交互一页（挂骰子教程系统）。

## 八、分期与工作量

| 期 | 内容 | 依赖 | 估算 |
|---|---|---|---|
| Phase 2a | 丙-1（标记层 + 元素详情浮层） | 元素表 + 坐标列；b5/b6 地图模块 | 中 |
| Phase 2b | 丙-2（真图层组装） | 乙（单源表）落地；图标库 | 大 |
| Phase 2c | 丙-3（世界总览图） | 世界点坐标列 | 中 |

> 建议：**不抢首期**——先甲 / 乙保「效果复现」，b4~b6 落地后按实测收益决定 2a→2b / 2c 顺序。

## 九、优点汇总（详解）

1. **交互最强**：从「看图的」升级到「点图的」（元素 → 详情 / 交互）；
2. **动态性**：数据变化即时反映（状态 / 新增 / 移除不用重绘）；
3. **架构统一**：探索 / 战斗同构，维护一套渲染器；
4. **数据价值最大化**：元素表 / 角色表（AI 高频维护）直接成为可视化内容；
5. **可扩展**：为「世界总览 / 地区切换 / 迷雾」等留全部门。

## 十、缺点与风险汇总（详解）+ 缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| 手绘保真 vs 图层化 | 丙-2 图标化降低沉浸感 | 丙-1 先保真交付；丙-2 作可选模式 |
| AI 标记稳定性 | 丙-1 依赖打标 / 热点输出 | 生成后校验 + 三级降级 |
| 坐标对齐 | 整图坐标系不可控 | 丙-1 用「图形自标记」绕过；丙-2 用网格吸附 |
| 工程量 | 渲染 / 管线重设计 | 分期独立；不阻塞主线 |
| 双写风险 | 元素表被 AI + 前端同时改 | 「渲染列约定」（note + 提示词） |
