> 2026-10-06 · 供确认稿 · 基于对骰子基座的代码级勘察（features/table、render、events、dashboard 等）

---

## 一、目标重述

**不再使用和显示骰子面板（独立浮层）**——把骰子面板的**全部功能**融入 **Mini HUD + DND 主面板**，让两者合为一个整体。
（硬性前提：骰子面板现有功能必须 100% 保全，且在 DND 侧的操作体验与骰子面板一致，尤其表格编辑必须"功能对等"而非只读。）

## 三、融合技术路径（三选）

### 路径 A：弹窗直调（弹窗≠面板）——已完成 ~80%
骰子原有 overlay 弹窗照常弹出（它们是"弹窗"，不是"面板"），DND 侧只做入口桥接。
- ✅ 已接：设置 / 掷骰 / 库存 / 地图 / 收藏夹 / 审核 / 交互总览 / 数据库可视化编辑器
- 待接：教程 / 卡片预览 / 对抗 / 燃烧 / 消息
- **优点**：零风险；**缺点**：覆盖不了"表格浏览"这种面板内核。

### 路径 B：视图嵌入（推荐主线）
把骰子的"视图区 HTML"渲染进 DND 容器，事件经**多宿主改造**继续生效：
1. **渲染直调桥**：`renderTableHostForDnd(tableName, containerEl)` → 直接调用 `renderTableContent` 输出到 DND 容器；
2. **事件多宿主改造**：`bind-events.ts` 的局部委托根（现为 `.acu-wrapper`）→ 扩展为"作用域根注册表"（DND 容器也纳入委托）；
3. **局部重渲染**：`refreshDndTableHost(tableName)` —— 复用 `renderInterface()` 的渲染逻辑但输出到 DND 容器。
- **优点**：风格可统一、可裁剪、完全体；**缺点**：改造面较大（bind-events 3000+ 行里的局部绑定），需分批推进。

### 路径 C：面板搬家（兜底 / 快速见效）
骰子面板根节点 `.acu-wrapper` 整体 `appendTo` DND 容器（打开时迁移、关闭时移回）。
- **优点**：**零重写、功能 100%**；1-2 批即可上线；**缺点**：UI 仍是骰子风格、fixed 定位需适配、状态机双管。

## 四、推荐方案：分层融合（A + B 为主，C 兜底）

### 4.1 表格功能（③的答案）——完整对等
- **Mini HUD「▼」内嵌区**：保持"表格列表"入口 →改为**点击表名→内嵌展示完整表格视图**（16 项全功能，可编辑）；
- **DND 主面板**：新增「数据表格」导航页（替代"弹骰子面板"路径），全功能表格工作区；
- **技术落点**：路径 B（渲染直调 + 事件多宿主 + 局部重渲染）。

### 4.2 功能视图嵌入
主面板「数据审核 / 变量管理 / 收藏夹 / 交互总览」4 项从"弹骰子面板"→**主面板内嵌渲染**（复用已通的 `renderAcuViewHtml` 并扩展为"渲染进主面板容器"）。

### 4.3 弹窗生态补齐
教程 / 卡片预览 / 对抗 / 燃烧 / 消息按需补桥。

### 4.4 面板退役
骰子面板展开触发器隐藏（可留开发者开关兜底），实现"不再显示骰子面板"。

## 六、风险与缓解

| 风险 | 缓解 |
|---|---|
| bind-events 局部绑定改造范围大 | "作用域根注册表"模式渐进；先在 b13.2 覆盖表格相关事件 |
| 面板状态机（activeTab / dashboard）以骰子面板为准 | 嵌入层维护"当前表"状态映射，不破坏原状态机 |
| 双态并存期冲突（z-index / 状态） | 分批验证；路径 C 兜底 |
| 样式隔离 | DND 容器加作用域类，骰子样式原样继承（不裁剪） |
